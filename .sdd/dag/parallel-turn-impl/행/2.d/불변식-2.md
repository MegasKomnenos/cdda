# 새 테스트 하네스 불변식

1. 출처: C:\cdda\.sdd\dag\parallel-turn-impl\결정\사용자확정-테스트하네스연결.md 「결정」과 「메인 결정」
   문면: 활성 행의 테스트 명령은 `build-tests.ps1`, `run-tests.ps1`, `verify-test-data.ps1`로 한정한다.
   목적: 실행 가능한 테스트 명령을 하나의 계약으로 고정한다.
2. 출처: C:\cdda\run-tests.ps1 매개변수와 C:\cdda\test-harness\TestHarness.psm1 `ConvertTo-NormalizedManifest`
   문면: 호출자는 빌드 기록, 새 실행 디렉터리, 숫자 seed, 정확한 테스트 이름을 명시한다. JSON 명세는 하나 이상의 논리 조각을 가진다. 와일드카드, 태그, 부분 문자열, 빈 목록, 미등록 이름, 중복 이름은 허용하지 않는다.
   목적: 호출자 선택과 실제 실행 집합을 축자로 대조한다.
3. 출처: C:\cdda\build-tests.ps1과 C:\cdda\test-harness\TestHarness.psm1 `Assert-BuildRecordCurrent`
   문면: `build-tests.ps1`은 소스 지문과 실행 파일 SHA-256에 묶인 `build.json`을 만든다. 소스나 실행 파일이 달라지면 `run-tests.ps1`은 종료 코드 3으로 중단한다.
   목적: 테스트 결과를 그 결과를 만든 소스와 실행 파일에 결속한다.
4. 출처: C:\cdda\run-tests.ps1
   문면: 테스트 통과와 테스트 실패는 논리 조각의 완료 결과다. 프로세스 충돌, 예기치 않은 종료, 진행 정지는 프로세스 실패다. 프로세스 실패에서는 미완료 논리 조각을 다시 실행한다.
   목적: 제품 실패와 실행기 실패를 다른 처분으로 남긴다.
5. 출처: C:\cdda\run-tests.ps1과 C:\cdda\test-harness\TestHarness.psm1 `Invoke-HarnessProcess`
   문면: 제어기는 프로세스 PID를 1분마다 확인한다. 초기화 중 90분, 초기화 뒤 30분 동안 진행이 없으면 프로세스를 종료한다. 중단된 제어기는 `run-tests.ps1 -Resume <실행 디렉터리>`로 재개한다.
   목적: 사망과 진행 정지를 검출하고 완료 조각을 보존한다.
6. 출처: C:\cdda\.sdd\dag\parallel-turn-impl\결정\사용자확정-테스트하네스연결.md 「메인 결정」 2~5항
   문면: 일반 구현 행은 수정한 동작을 직접 검사하는 표적 테스트만 실행한다. 작업자는 수정 범위를 확정한 뒤 정확한 테스트 이름과 논리 조각을 자식 행에 기록한다. 일반 구현 행은 데이터 consistency를 반복하지 않는다.
   목적: 구현 위험과 테스트 비용을 같은 행에 귀속한다.
7. 출처: C:\cdda\.sdd\dag\parallel-turn-impl\결정\사용자확정-테스트하네스연결.md 「메인 결정」 6~8항
   문면: 행 2.14는 최종 빌드, 데이터 검증, 전체 일반 테스트, 기능 인수, 성능 인수를 소유한다. 전체 일반 테스트는 최종 빌드 기록의 `hidden: false` 이름 전건을 명시적 JSON 명세에 고정한다. 후행 검증과 싱크는 같은 전체 테스트를 반복하지 않는다.
   목적: 전체 인수 비용을 최종 소스 형상에 한 번만 지불한다.
8. 출처: C:\cdda\run-tests.ps1 결과 조립과 C:\cdda\verify-test-data.ps1 결과 조립
   문면: 테스트 생산 행은 빌드 기록 경로와 SHA-256, JSON 명세 경로와 SHA-256, 실행 디렉터리, `result.json`, 조각별 `execution_status`, 조각별 `outcome`, 모든 시도 증거를 보고한다. 데이터 검증 생산 행은 `verification.json`과 그 파일의 빌드 ID, 실행 파일 SHA-256, 소스 지문을 보고한다.
   목적: 후행 행이 테스트를 실행하지 않고 결과의 완전성과 귀속을 판정하게 한다.
9. 출처: C:\cdda\.sdd\dag\parallel-turn-impl\결정\사용자확정-테스트하네스연결.md 「메인 결정」 4항과 C:\cdda\run-tests.ps1
   문면: 테스트 생산 행은 `C:\cdda\build\dag-parallel-turn-impl\<행번호>\<build_id>\` 아래에 명세와 실행 디렉터리를 둔다. 새 실행 디렉터리는 존재하지 않아야 한다. 같은 소스와 빌드 기록의 중단 실행이나 완료 실행만 `-Resume`으로 연다. 완료 논리 조각은 다시 실행하지 않는다.
   목적: 병행 행과 재시도가 서로의 실행 증거를 덮어쓰지 않게 한다.
10. 출처: C:\cdda\run-tests.ps1 종료 처리
   문면: 종료 코드 0은 모든 테스트 통과다. 종료 코드 1은 완료된 테스트 실패다. 종료 코드 2는 명세나 선택 결함이다. 종료 코드 3은 빌드 기록, 소스, 실행 파일, 검증 기록의 불일치다.
   목적: 작업자가 제품 실패와 하네스 계약 실패를 같은 처분으로 합치지 않게 한다.
