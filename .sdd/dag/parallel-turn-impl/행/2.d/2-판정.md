# 행 2 충족성 판정

행 2의 전건을 현재 문면대로 완주해도 사용자 승인 범위와 인계문 요구가 모두 닫히지 않는다. 기준 실행의 선행 조건, 측정 요소별 감사표, 명령 생성 비용 상한, 상태 검증값의 의미가 검사 가능한 완료 기준에 빠져 있다.

## 지적

### [중대] 기준 실행이 구현 편집보다 뒤에 배치돼 선행 조건을 충족할 수 없다

- 내용: 인계문 16.1절은 병렬화 파일을 편집하기 전에 Git 상태, 전체 테스트, 기준 10,000턴 프로파일, 실행 파일 해시를 확보하라고 요구한다. 기존 테스트가 실패하면 구현 코드를 편집하지 않아야 한다. 그러나 파견표는 구현 전개 2.6부터 2.13까지를 실행한 뒤에야 인수 전개 2.14를 실행한다. 2.14/V-01은 기존 실패에서 구현 편집 없이 차단하라고 요구하지만, 그 시점에는 앞선 구현 노드가 이미 완료됐다. 2.14/V-03은 최종 직렬·병렬 실행만 요구하므로 기준 프로파일과 실행 파일 해시도 닫지 않는다.
- 근거: 인계문 16.1절 740~750행. 특히 742~746행은 전체 테스트, 기준 프로파일, 실행 파일 해시, 실패 시 편집 금지를 정한다. `파견표.md:12-20`은 2.6부터 2.14까지의 순차 선행을 정한다. `행/2.d/14.md:56-60`의 V-01~V-05에는 기준 프로파일 실행과 실행 파일 해시 검사가 없다.
- 처분 의견: 수리 가능

### [중대] 13개 측정 요소의 감사표와 fail-closed 판정이 전건 완료 기준에 없다

- 내용: 인계문은 각 측정 요소마다 입력, 모든 쓰기, 도달 가능한 전역 접근, 난수 호출, 적용 대상을 표로 닫으라고 요구한다. 하나라도 열리면 그 측정 요소를 직렬 경로에 둬야 한다. 2.9/M-05는 지도 그룹의 전역 접근·쓰기·난수 표만 닫는다. 2.7/C-01은 `turn_input_state`의 입력 전건을 구현하지만 측정 요소별 다섯 열 감사표를 요구하지 않는다. 2.10~2.12의 완료 기준에도 플레이어, 음향, 생물 측정 요소별 감사표와 fail-closed 판정이 없다. 따라서 13개 표가 없어도 각 노드가 완료될 수 있다.
- 근거: 인계문 9.1절 319~346행과 9.5절 518~522행. `행/2.d/불변식.md:29-32`도 같은 fail-closed 규칙을 고정한다. `행/2.d/7.md:56-60`의 C-01~C-05에는 측정 요소별 감사표가 없다. `행/2.d/9.md:60`의 M-05만 지도 범위의 표를 요구한다. `행/2.d/10.md:56-60`, `11.md:56-60`, `12.md:56-60`에는 나머지 측정 요소의 다섯 열 감사표가 없다.
- 처분 의견: 수리 가능

### [중대] 명령 생성 비용을 제한하는 메모리·분할 완료 기준이 빠졌다

- 내용: 인계문 11절은 작업자별 변경 레코드 메모리를 미리 할당하고 턴 사이에 재사용하라고 요구한다. 병합기는 대상별 배열이나 버킷으로 변경 레코드를 분할해야 한다. 턴 입력 상태는 전체 게임 객체를 턴마다 깊은 복사하면 안 된다. 현재 C-01~C-05는 값·불변 보기, 정렬 배열, k-way 병합을 요구하지만 메모리 재사용, 대상별 분할, 전체 게임 객체 깊은 복사 금지를 검사하지 않는다. 이 세 요구를 어겨도 기능 시험과 결과 동등성 시험은 통과할 수 있으므로 성능 목표를 닫지 못한다.
- 근거: 인계문 11절 632~645행. 특히 636~639행은 미리 할당, 재사용, 대상별 분할, 전역 정렬 금지를 정한다. 645행은 턴마다 전체 게임 객체를 깊은 복사하지 못하게 한다. `행/2.d/7.md:56-60`의 C-01~C-05와 `행/2-보고.md:29`의 11절 1~8항 배정에는 세 요구를 검사하는 기준이 없다.
- 처분 의견: 수리 가능

### [중대] 상태 검증값 동등성 검사가 상수나 불완전 직렬화를 배제하지 않는다

- 내용: 인계문은 의미 있는 게임 상태를 정해진 순서로 직렬화하고 포인터 주소와 할당 주소를 제외한 고정 길이 상태 검증값을 요구한다. 현재 E-05, B-05, I-05, V-02는 작업자 수와 제출 순서 사이의 상태 검증값 동등성만 검사한다. 상태 직렬화의 필드 전건, 정해진 순서, 주소 제외, 의미 있는 상태 변경에 대한 민감도는 완료 기준에 없다. 상수 검증값이나 일부 필드만 직렬화한 검증값도 동등성 시험을 통과할 수 있다.
- 근거: 인계문 4.3절 125행과 17.1절 871~879행. `행/2.d/8.md:60`, `12.md:60`, `13.md:60`, `14.md:57`은 동등성 또는 완전 조립 시험만 요구한다. 상태 직렬화 계약과 변이 민감도 시험을 요구하는 행은 판정 대상에서 확인되지 않았다.

- 판정 코퍼스 밖 제품 소스와 아직 생성되지 않은 자식 행에는 근거를 확장하지 않았다.
