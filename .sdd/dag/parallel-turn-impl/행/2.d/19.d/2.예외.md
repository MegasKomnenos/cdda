# 행 2.19.2 예외 처분

## 처분

일곱 번째 실행은 B-10 시작 측정에서 멈췄다. 시작 JSON과 전체 테스트 증거는 없다. 현재 실패는 B-10의 전건 비교가 불가능해서 발생하지 않았다. 측정 스크립트가 Git의 stdout을 동기로 모두 읽은 뒤 stderr를 읽어서 발생했다.

행 파견문은 여덟 번째 실행에서 두 스트림을 동시에 읽도록 보강했다. 파견표의 행 2.19.2 상태는 `미착수`로 되돌렸다.

측정 스크립트는 stdout 읽기가 끝난 뒤 stderr를 동기로 읽는다.

```text

  :40
[/실측기]
```

루트의 Git diff는 줄바꿈 경고를 stderr에 쓴다. 자식 Git 프로세스는 stderr 파이프가 차면 stderr 소비를 기다린다. 부모 측정 프로세스는 stdout 종료를 기다리므로 두 프로세스가 서로 기다린다.

## 실행 횟수 반증

사용자 배경은 이번 실행을 네 번째 실행이라고 설명한다. 현재 행 파견문과 보존 파일은 앞선 실행을 여섯 번 기록한다. 이번 실행의 좌표 이름은 `turn-2192-seventh-*`다. 따라서 현재 실물 기준 실행 횟수는 일곱 번이다.

이 횟수 차이는 처분을 바꾸지 않는다. 일곱 번째 실패 원인은 닫힌 코드 결함이다. 보수 기본형도 진단 실행에서 성립했다.

## 행 파견문 보강

행 파견문은 여덟 번째 실행에 아래 조건을 추가했다.

1. 측정 스크립트 이름과 모든 증거 파일 이름은 `turn-2192-eighth-*`를 쓴다.
2. `Invoke-GitBytes`는 stdout과 stderr의 비동기 소비를 모두 시작한 뒤 기다린다.
3. 비동기 작업의 반환값은 함수 출력에 섞이지 않게 버린다.
4. 일곱 번째 실행의 파일은 새 실행의 증거로 쓰지 않는다.
