## 임무

1. 불변식 세 파일과 정본 일곱 파일을 읽는다. H-01의 현재 상태를 실측한다.

3. `C:\cdda\build\turn-21912-final-test-game2`가 없을 때만 `runner.ps1`을 쓴다. `started.txt`가 있으면 새 실행을 시작하지 않는다.
4. `started.txt`가 있으면 `runner-pid.txt`의 프로세스와 `terminal.txt`를 확인한다. 기존 실행을 기다리거나 수확한다.
5. ProcDump 실행 파일의 Authenticode 상태와 서명자를 검사한다. 검사가 H-03과 다르면 테스트를 시작하지 않는다.
6. `runner.ps1`은 `started.txt`를 먼저 쓴다. 그다음 원본 두 JSONL 파일을 보존한다.
7. `runner.ps1`은 `System.Diagnostics.Process`로 ProcDump를 시작한다. `StandardOutputEncoding`과 `StandardErrorEncoding`은 `[System.Text.Encoding]::Unicode`로 지정한다.
8. ProcDump 대기 문구는 `ReadLineAsync()`와 30초 제한 시간으로 판별한다. `StandardOutput.Peek()`은 사용하지 않는다.
9. ProcDump가 대기 상태에 들어가면 별도 `System.Diagnostics.Process`로 `powershell.exe`를 시작한다. 인자는 `-NoProfile -ExecutionPolicy Bypass -File C:\cdda\test-game.ps1`이다.
10. 테스트용 PowerShell 프로세스의 표준 출력과 표준 오류는 비동기로 끝까지 읽는다. `WaitForExit()` 직후 `ExitCode`를 저장한다.
11. `runner.ps1`은 `finally`에서 ProcDump를 최대 15초 기다린다. ProcDump가 남으면 새 실행기가 시작한 ProcDump만 종료한다.
12. `runner.ps1`은 `finally`에서 생성 JSONL 파일을 격리한다. 보존 원본을 원래 경로에 복원한다.
13. `runner.ps1`은 모든 산출과 복원 결과를 쓴 뒤 `terminal.txt`를 마지막으로 쓴다.
14. `Start-Process -WindowStyle Hidden`으로 `runner.ps1`을 한 번 시작한다. 실행기 PID를 `runner-pid.txt`에 기록한다.
15. `terminal.txt`가 설 때까지 30초 이하 간격으로 포그라운드에서 기다린다. 도구 호출이 끝났다는 사실을 테스트 종료로 해석하지 않는다.
16. terminal 뒤 실행기, `cata_test-tiles`, ProcDump 프로세스가 없는지 확인한다. 제품 diff, 원본 두 JSONL, `.core`, Windows Error Reporting 키를 다시 측정한다.
17. 기존 `12-보고.md`는 이전 실패 기록이다. 새 `terminal.txt`가 서기 전에는 기존 보고를 덮어쓰지 않는다.
18. `exit.txt` 값과 무관하게 같은 전체 테스트를 반복하지 않는다. 종료 증거와 복원 결과를 보고하고 `DONE`으로 반환한다.
