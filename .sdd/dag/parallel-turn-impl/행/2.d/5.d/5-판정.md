# 수리 뒤 행 2 충족성 재검 판정

수리한 네 항목은 현재 완료 기준에 연결됐다. 구현 시작 시점의 루트와 서브모듈 커밋 해시 기록은 완료 기준에 연결되지 않았다.

## 지적

### [중대] 구현 시작 시점의 루트와 서브모듈 커밋 해시를 검사하지 않는다

- 내용: 인계문 14절은 병렬화 파일 편집 전에 루트와 서브모듈에서 각각 `git rev-parse HEAD`를 실행하게 한다. 행 2.19의 CK-1과 CK-2는 두 Git 상태 파일만 요구한다. V-01도 루트·서브모듈 “상태”만 묶어서 지목한다. 커밋 해시 필드, 두 `rev-parse` 명령, 해시 형식 검사는 행 2.19의 완료 기준에 없다. `git status --short --branch` 출력만 두 파일에 저장해도 CK-1, CK-2, V-01을 통과할 수 있다. 그러면 구현 시작 기준 커밋을 고정하지 못한다. 기준선의 생성 시점 해시는 구현 시작 시점에 Git 상태가 달라질 수 있다는 인계문 14절의 요구를 대신하지 않는다.
- 근거: 인계문 `cdda-parallel-turn-implementation-handoff.md:707-716`은 편집 전 네 명령을 닫힌 코드 블록으로 정한다. 그중 `:711`과 `:713`이 루트와 서브모듈의 `rev-parse HEAD`다. `행/2.d/19.md:11`의 CK-1~CK-2는 Git 상태 기록만 요구하고, `:41`의 V-01도 커밋 해시를 명시하지 않는다. `행/2-보고.md:36,69`은 V-01을 같은 상태 파일로만 추적한다. 재현 출력은 아래와 같다.

  ```text
  인계문 710: git status --short --branch
  인계문 711: git rev-parse HEAD
  인계문 712: git -C cataclysm-dda status --short --branch
  인계문 713: git -C cataclysm-dda rev-parse HEAD
  행 2.19 11: CK-1. 루트 Git 상태 ... CK-2. 서브모듈 Git 상태 ...
  행 2.19 41: V-01 | 루트·서브모듈 상태, 전체 테스트, 기준 10,000턴 프로파일, JSON 실행 파일 해시 ...
  ```
- 처분 의견: 수리 가능
