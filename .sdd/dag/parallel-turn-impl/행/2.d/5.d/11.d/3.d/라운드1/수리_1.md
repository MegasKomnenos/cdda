## R1-1 전개 지시 11항이 CK-8의 상태·커밋 증거를 싱크 판정에서 누락한다

### 위치

`.sdd/dag/parallel-turn-impl/행/2.d/19.md` 61~61행. 라운드 1 사본의 같은 61~61행이다.

### 기준

`C:/cdda/.sdd/dag/parallel-turn-impl/행/2.d/5.d/11.d/3.d/동결.md` 「불변식 목록」은 `2.19.z`가 성공한 작업자 상태 기록, 두 상태 출력, 두 시작 커밋 기록, 두 형식·동일성 검사, 성공한 전체 테스트, 기준 프로파일, 실행 파일 해시를 모두 대조한다고 정한다.

```
크리티컬 영역의 닫힌 목록은 성공 `DONE`, 기준 출력 경로 선재의 `기준출력선재`, 기존 전체 테스트 실패의 `기존테스트실패`, 두 실패 보고의 증거 보존, `2.19.z` 성공 한정, 행 `2.6` 차단, 새 원장 부재, 새 필드 부재, 새 공개 함수 부재, 새 JSON 키 부재, `이음새: 없음` 유지다. 검증런은 행 `2.19`의 편집 귀속과 변경 문면을 함께 대조한다. 다른 `없음` 문면이나 문자열 0건만으로 다섯 부재 검사를 통과시키지 않는다.
```

사본 11행의 CK-8도 같은 증거 전건을 `2.19.z`의 완결 조건으로 둔다.

```
CK-8. 성공한 기준 실행만 `DONE`으로 닫는다. `2.19.z`는 성공한 작업자 상태 기록, 두 상태 출력, 두 시작 커밋 기록, 두 형식·동일성 검사, 성공한 전체 테스트, 기준 프로파일, 실행 파일 해시를 모두 판정한 경우에만 완결한다.
```

### 영향

현행 전개 지시 11항은 두 상태 출력, 두 시작 커밋 기록, 두 형식·동일성 검사를 판정 조건에서 빼고 있다. 따라서 `2.19.z`는 그 증거가 없는 성공한 작업자 상태 기록, 전체 테스트, 기준 프로파일, 실행 파일 해시만으로 완결할 수 있다. 행 `2.6`은 완결한 `2.19.z` 뒤에 열리므로, 구현 편집 전에 필요한 시작 커밋 검증이 누락된 상태로 행 `2.6`이 열릴 수 있다.
