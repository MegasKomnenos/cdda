두 귀속의 합집합이 worktree 변경 전건을 덮는다. 어느 완료 기준에도 귀속되지 않은 편집은 없다.

### 다섯 부재의 근거

**새 원장 부재.** 편집분이 만든 파일이 없다. `git status --porcelain`에서 `행/2.d/19.md`는 `M`(수정)이고 새 파일이 아니다. 국면의 상태 구조 원장인 `이음새.md`에 행 2.19를 지목하는 줄이 없다 — 그 파일에서 `2.19`를 찾으면 0건이고, S-01부터 S-11까지의 「노출 행」·「연결 행」 열 어디에도 2.19가 없다. 이 0건은 부재 검사의 유일한 근거가 아니라, 편집분 판독이 낸 결론(편집분에 원장 생성이 없다)을 원장 실물에서 다시 확인한 것이다.

**새 필드 부재.** 행 파일의 필드는 frontmatter 키와 `- <이름>:` 슬롯이다. 커밋본 `0f1d037:행/2.d/19.md`, 현행, 이 런의 앵커 셋에서 슬롯 이름 집합을 각각 뽑아 대조했다. 세 집합이 완전히 같다(차집합 양방향 0건, 슬롯 19개). frontmatter도 셋 다 같은 네 키(`행`·`유형`·`격리`·`base`)다. 편집분은 기존 슬롯의 값만 바꿨다.

**새 공개 함수 부재.** 편집분은 마크다운 산문과 PowerShell 명령 인용 넷(`git status --short --branch`, `git rev-parse HEAD`, `git -C cataclysm-dda status --short --branch`, `git -C cataclysm-dda rev-parse HEAD`)만 담는다. 함수 선언이 될 수 있는 코드가 편집분에 없다. 이 넷은 기존 Git 명령의 호출이지 새 함수의 선언이 아니다.

**새 JSON 키 부재.** 편집분에 JSON 리터럴도 JSON 스키마 서술도 없다. 편집분이 JSON을 거론하는 자리는 셋이고 셋 다 기존 키의 소비다 — CK-5의 "성공한 기준 프로파일 JSON에서 실행 파일 해시를 기록한다", V-01의 "JSON 실행 파일 해시", 전개 지시 16항의 금지문 "새 JSON 키 …를 만들지 않는다"다. 실행 파일 해시는 프로파일러가 이미 내는 값이고, 행 2.19는 그것을 읽어 적을 뿐이다.

**`이음새: 없음` 유지.** 33행의 `이음새:` 슬롯 값이 커밋본·현행 모두 `없음`으로 시작한다. 커밋본의 문면은 "없음. 기준 실행은 새 상태 구조나 새 노드 주입 인터페이스를 만들지 않는다"였고, 현행은 "없음. 기준 실행은 새 원장, 새 필드, 새 공개 함수, 새 JSON 키, 새 노드 주입 인터페이스를 만들지 않는다"다. 편집은 `없음`이라는 값을 유지한 채 그 뒤 설명을 「상태 구조」에서 네 낱말의 닫힌 목록으로 폈다. 이음새 원장 `이음새.md`에 행 2.19의 S행이 없다는 사실이 이 값과 맞는다.

## 정본 문서와의 대조

파견문이 정본으로 지정한 두 문서를 실물과 맞췄다.

- `행/2.d/5.d/4-판정.md` 「지적」의 중대 항목은 수리 전 상태를 기술한다 — "행 2.19의 반환은 두 실패 분기에서도 `DONE` 하나뿐이다", "행 2.19과 파견표에는 2.19.z를 미완결로 남기거나 2.6을 차단하는 상태 전이 규칙이 없다". 두 진술 모두 현행 `행/2.d/19.md`에서 더는 성립하지 않는다. 32행이 두 실패 분기에 `예외`를 배정하고, 11행 CK-8과 34행과 60행이 차단 규칙을 싣는다.
- `행/2.d/5.d/11.d/2-보고.md`(수리 행 2.5.11.2의 보고)의 주장 전건을 위 표에서 실물과 맞췄다. 그 보고의 「이음새 광고」("없음. 행 `2.19`는 새 원장, 새 필드, 새 공개 함수, 새 JSON 키, 새 노드 주입 인터페이스를 만들지 않는다")와 「이월 사슬」도 현행 문면과 일치한다.

## 반증 의무

파견문·입력과 어긋난 지점 하나를 기재한다.

파견문 실행 지침 9항은 "라운드 커밋은 verify-rounds SKILL.md §7 「라운드 커밋」 절차를 그대로 따른다"고 지시하고, 같은 항이 commit-harness 실행도 요구한다. do-dag `계약/검증런.md` 「실행 규율」은 그 둘을 명시로 금지한다 — 【커밋금지 · 작업자·조사·브리핑·렌즈·검증런은 커밋하지 않는다】와 "verify-rounds §7 「라운드 커밋」의 commit-harness 전건 실행을 하지 않는다"다. 이 런은 계약을 따라 커밋하지 않았다. 근거는 같은 계약 「임무」 3항("verify-rounds SKILL.md와 이 계약이 어긋나면 이 계약이 이긴다")과 파견문 `계약:` 슬롯이 그 계약을 이 행의 역할 계약으로 지정했다는 사실이다. 수리 2건은 worktree 실물 `.sdd/dag/parallel-turn-impl/행/2.d/19.md`에 남아 있고, 커밋 자리는 이 노드의 싱크다.

그 밖에 파견문·입력과 어긋난 지점은 없다.
