## 브리핑

행 2.19.9(접근 위반 덤프 재현, gpt-5.6-terra med)가 두 번째 파킹으로 국면을 다시 조기 종결시켰다. 첫 파킹(오케 12기)의 사유는 실행 계정의 HKLM 권한 부재였고, 사용자확정 결정(`결정/사용자확정-LocalDumps권한.md`)이 권한 부여로 해소했다. 두 번째 파킹(오케 13기)의 사유는 다르다 — Codex CLI가 `danger-full-access` 샌드박스에서도 HKLM 레지스트리 쓰기를 담은 pwsh 명령을 실행 전에 거부했다. 증거: `행/구시도-2.19.9/_로그_2.19.9.txt`(재파견 정리로 이동 보존한 두 번째 시도 로그)의 `CreateProcess { message: "Rejected(... rejected: blocked by policy") }` 2회(전체 실행 스크립트와 키 생성만 담은 축소 스크립트 모두). 같은 로그에서 레지스트리 읽기(Test-Path) 명령은 통과했다. 행 보고(`행/2.d/19.d/9-보고.md`)는 미실행·산출 전무를 기록했고, 메인이 출력 경로 여섯의 부재를 실측으로 재확인했다.

상신 사유: 목표(덤프 확보)가 실행기 정책이라는 환경 제약에 막혀, 배정 변경 없이는 닫히지 않는다.

## 메인 결정 (사용자 축자 아님)

**행 2.19.9를 `opus med`로 재배정하고 미착수로 되돌려 재파견한다.**

근거:

1. 차단 주체는 Windows 권한이 아니라 Codex 실행기의 명령 정책이다. 계정 `DESKTOP\wogud`의 하위 키 생성·삭제는 메인 세션의 비승격 셸에서 검증됐으므로, 같은 세션에서 도는 Claude 계열 에이전트는 이 행을 수행할 수 있다.
2. 배정 도출: 배정표 대비표에서 gpt-5.6-terra의 동급 Claude 모델은 opus다. 노력 med는 유지한다 — 임무의 질적 난도는 변하지 않았다. 하위 티어 대체가 아니라 동급 계열 교체이므로 「크레딧·차단 시 하위 티어로 대체하지 않는다」에 저촉되지 않는다.
3. 상신중계 4판정: 사용자 확정 문면을 바꾸지 않고(권한 부여·재개 결정은 그대로 집행된다), 비가역 행위가 아니며, 국면 범위 밖 실질을 들이지 않고, 비동등한 결과의 선택이 남지 않는다. 따라서 메인이 결정한다.
4. 행의 완료 기준·경로·불변식은 바꾸지 않는다. 두 번째 시도가 산출을 만들지 않았으므로 새 경로 재배정은 불필요하다(여섯 경로 전부 부재 실측).
