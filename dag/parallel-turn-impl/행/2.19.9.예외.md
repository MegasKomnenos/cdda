## 처분

처분은 `미착수`다. 행 2.19.9는 장기 실행 수명 계약을 보강하면 다시 파견할 수 있다. 제품 파일 수리는 필요하지 않으므로 수리 행은 추가하지 않는다.

행 2.19.9는 새 실행 좌표 `C:\cdda\build\turn-2199-av-repro6\`를 사용한다. 독립 실행기가 ProcDump와 테스트를 직접 시작한다. 독립 실행기는 에이전트의 도구 호출과 별도 수명으로 끝까지 실행한다. `runner-terminal.txt`가 생기고 두 프로세스가 끝난 뒤에만 행이 결과를 판정한다.

## 이전 실패와 이번 실패의 관계

산출 누락의 종류는 같다. 두 실행 모두 종료 코드 파일과 출력 파일을 확보하지 못했다.

근본 원인은 다르다. 이전 실행은 테스트가 끝난 뒤 `Start-Process -PassThru` 객체에서 종료 코드를 잃었다. 이번 실행기는 `System.Diagnostics.Process`를 직접 사용했다. 그러나 에이전트는 장기 실행 도구 호출이 돌아온 사실을 테스트 종료로 오인했다. 로그에는 종료 선언 뒤에도 테스트와 ProcDump가 살아 있었다. 실행기는 종료 뒤에만 출력 파일과 종료 코드 파일을 쓰도록 구성돼 있었다. 현재 두 프로세스는 없고 여섯 파일도 없다. 따라서 이번 실패의 근본 원인은 에이전트가 실행기 종결 전에 반환한 수명 관리 결함이다.

### 이전 실패와 이번 실패의 관계

표층 반환은 이전 실패와 같다. 그러나 `repro6`은 테스트 실행 파일을 시작하지 않았다. `test-pid.txt`가 없고 stdout과 stderr는 실행 전 생성된 빈 파일이다. 종료 코드가 없는 이유도 테스트 종료 코드의 소실이 아니다.

이번 근본 원인은 이전 세 보강이 다루지 않은 ProcDump UTF-16LE 출력이다. `repro5` 보강은 테스트 프로세스의 종료 코드 수집을 바꿨다. 첫 `repro6` 보강은 실행기 수명과 종결 표식을 바꿨다. 어느 보강도 ProcDump의 출력 인코딩과 차단형 `Peek()`을 다루지 않았다.

### 행 파일 보강

행 2.19.9에는 아래 다섯 변경을 적용했다.

1. 새 실행 좌표를 `C:\cdda\build\turn-2199-av-repro7\`로 바꿨다.
2. `repro5`와 `repro6` 실행 좌표를 읽기 전용 증거로 지정했다.
3. ProcDump의 stdout과 stderr를 UTF-16LE로 디코딩하도록 지정했다.
4. 대기 문구 판별을 `ReadLineAsync()`와 제한 시간으로 지정했다.
5. 차단형 `StandardOutput.Peek()`을 금지했다.

행 2.19.10은 이 예외 기록을 정본과 읽기 목록에서 이미 지정한다. 따라서 행 2.19.10 파견문은 고치지 않았다.

### 반증 의무

Codex 비대화식 실행기가 원리적으로 종료 코드와 출력 파일을 보존할 수 없다는 가설은 분리 실측과 어긋난다. ProcDump가 대기 상태에 들어가지 못했다는 `repro6` 실행기의 묵시적 판정도 UTF-16LE 실물과 어긋난다.
