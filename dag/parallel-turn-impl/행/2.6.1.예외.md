# 예외 기록: 행 2.6.1 미커밋 기준선

## 처분

처분은 `미착수`다. 행 2.6.1은 처음부터 다시 파견할 수 있다. 별도 커밋과 수리 행은 필요하지 않다.

행 2.6.1 파견문에 `0단계 기준선` 절을 추가했다. 이 절은 산출물의 현재 축자를 기준선으로 사용한다. `vr.py 앵커`가 복원 기준을 보존한다. 행 2.6.1은 `verify-rounds` §7 0단계 8항의 Git 상태를 장부에 기록하되, 미커밋 상태만으로 라운드 1을 막지 않는다.

사용자 확정 기록 `C:\cdda\.sdd\dag\parallel-turn-impl\결정\사용자확정-2.6.1중단.md`를 행 2.6.1의 `정본:`과 `읽기 목록:`에 추가했다. 이 결정은 앞 실행의 중간산출을 삭제하고, 라운드 1이 적용한 수리를 보존한 채 행 2.6.1을 처음부터 재파견하도록 정한다.

상신 사유 넷에는 해당하지 않는다. 이번 보강은 사용자 확정 문면과 불변식을 바꾸지 않는다. 비가역 행위와 코퍼스 밖 발명도 요구하지 않는다.

## 반환 형식

입력 반환 텍스트의 첫 줄은 `동결 착수 전 필수 점검(§7 0단계 7·8항)에서 진행 불가 조건을 확인했다.`다. 이 문장은 공통 반환어휘 `DONE`, `DONE-비준`, `상신`, `예외` 밖이므로 `반환형식위반`이다. 뒤쪽 코드 울타리 안의 `예외`는 첫 줄을 대신하지 않는다.

## 실측

```text
[Git 상태 실측]
명령: git status --short -- <동결문 산출물 13개 경로>; git ls-files --error-unmatch -- <각 경로>; git diff --cached --quiet
작업 디렉토리: C:/cdda
미추적: 11개
수정: 1개 — .sdd/dag/parallel-turn-impl/파견표.md

Git 색인: 비어 있음, git diff --cached --quiet exit 0
[/Git 상태 실측]
```

입력 반환은 미추적 파일이 12개라고 적었다. 실제 미추적 파일은 11개다. 입력 반환은 깨끗한 `이음새.md`를 별도로 언급했으므로 총 대상 수 13개와도 내부적으로 맞지 않았다.

## 근거 대조

별도 기준선 커밋은 현행 `do-dag` 절차와 충돌한다. `계약/검증런.md`는 검증런의 커밋을 금지한다. 제품 수리는 노드 싱크가 커밋하고, 설계 수리는 국면 종결 뒤 메인이 이관한다. 행 2.6.1의 대상은 전개 2.6이 만든 미커밋 설계 자산이다.

같은 행의 사용자 확정 기록도 별도 커밋을 요구하지 않는다. `사용자확정-2.6.1중단.md`는 앞 실행을 정리한 뒤 행 파일과 배정을 유지하고 행 2.6.1을 재파견하도록 정한다. 따라서 입력 반환의 별도 커밋 처방은 정본과 어긋난다.

## 파견표와 행 파일

파견표에서 행 2.6.1의 상태를 `예외`에서 `미착수`로 바꿨다. 선행 2.6은 `완`이다. 후행 2.6.2와 2.6.9, 싱크 2.6.z의 선행 관계는 바꾸지 않았다. 모델 열 `sonnet med`도 바꾸지 않았다.

행 2.6.1 파견문은 아래 세 사실을 명시한다.

1. 현재 산출물 13개 파일이 검증 기준선이다.
2. 앵커가 복원 기준이다.
3. 앞 실행의 라운드 1 수리 세 건은 현재 기준선에 포함한다.

## 반증 의무

입력 반환의 핵심 Git 상태는 재현됐다. 그러나 미추적 파일 수와 별도 커밋 처방은 실물과 정본에 어긋난다.

그 외 반증은 없다. 검사 범위는 파견표의 행 2.6, 2.6.1, 2.6.2, 2.6.9, 2.6.z다. 행 2.6과 2.6.1의 파견문, 행 2.6 보고, 완료 신호, 불변식 네 파일, `계약/검증런.md`, `verify-rounds` §7 0단계, 사용자 확정 기록 두 파일도 검사했다.

## 검산

지급된 검산 명령은 처분 전과 처분 뒤에 모두 exit 0이었다. 출력은 `[dag_check] 무발견 (drive: 서식·어휘·칸 계약·폐쇄·수렴·순환·좌표 실재·게이트 결정·운전)`이다.

지급된 마커 명령은 하위 명령이 없어서 사용법을 출력하고 exit 2로 끝났다. 행 2.6.1은 싱크가 아니므로 lease와 마커 상태를 바꾸지 않았다.
