# 행 2.19.12 예외 처분

## 처분

처분은 `미착수`다. 행 2.19.12는 행 2.19.9의 종결 증거 수집 방식을 재사용하지 않았다. 새 실행 좌표와 직접 프로세스 실행을 지정하면 다시 파견할 수 있다.

행 2.19.12는 `C:\cdda\build\turn-21912-final-test-game2`를 새 실행 좌표로 사용한다. 기존 `C:\cdda\build\turn-21912-final-test-game`은 실패 증거로 보존한다. 제품 파일 수리는 필요하지 않으므로 수리 행은 추가하지 않는다.

상신 사유 넷에는 해당하지 않는다. 이번 처분은 불가침과 사용자 확정 문면을 바꾸지 않는다. 이번 처분은 비가역 행위와 코퍼스 밖 발명을 요구하지 않는다.

## 실패 분류

이번 실패는 행 2.19.7의 하네스 강제 종료 패턴이 아니다. 독립 실행기는 시작 후 128.712초 안에 사라졌다. 원 반환 파일은 공통 반환어휘에 맞는 103바이트 예외 반환이다. 원 로그도 `tokens used`와 토큰 수로 정상 종료 문면을 남겼다.

이번 실패는 행 2.19.9의 종결 증거 수집 실패 계열이다. 실행기와 `cata_test-tiles`는 모두 종료했다. 그러나 `stdout.txt`, `stderr.txt`, `exit.txt`, `terminal.txt`는 없다. 즉, 실행기는 테스트 종료 결과를 파일로 영속화하지 못했다.

실행기가 사라진 직접 원인은 원 실행 산출만으로 확정할 수 없다. 원 실행은 오류 파일과 종료 코드 파일을 남기지 않았다. 따라서 특정 PowerShell 예외나 외부 프로세스 종료를 사실로 단정하지 않는다.

## 행 2.19.9 수정의 재사용 대조

기존 행 2.19.12 파견문과 실행기는 행 2.19.9의 최종 수정을 재사용하지 않았다.

```text
[문면 실측]
명령: Select-String -SimpleMatch
시각: 2026-08-26T14:20+09:00
대상: 처분 전 행 2.19.12 파견문
ProcDump: 0회
System.Diagnostics.Process: 0회
StandardOutputEncoding: 0회
ReadLineAsync: 0회
StandardOutput.Peek 금지: 0회
Start-Process: 2회
[/문면 실측]
```

행 2.19.9의 `repro7` 실행기는 같은 환경에서 종료 코드와 출력 파일을 보존했다. 그 실행기는 ProcDump를 먼저 시작했다. 그 실행기는 ProcDump 출력을 Unicode로 디코딩했다. 그 실행기는 테스트를 `System.Diagnostics.Process`로 직접 시작했다. `runner-terminal.txt`도 마지막에 남겼다.

행 2.19.12에는 같은 방식을 적용한다. 새 실행기는 ProcDump를 먼저 대기시킨다. 새 실행기는 별도 PowerShell 프로세스로 `test-game.ps1`을 한 번 실행한다. 새 실행기는 직접 실행한 PowerShell 프로세스의 출력과 종료 코드를 저장한다. 이 구조는 `test-game.ps1`의 수명을 체크포인트 실행기와 분리한다.

ProcDump의 Unicode 수정은 이번 원 실행의 직접 실패 원인으로 확인되지 않았다. 원 실행은 ProcDump를 시작하지 않았기 때문이다. 그러나 ProcDump를 새로 적용하면 행 2.19.9가 실측한 UTF-16LE 대기 문구를 처리해야 한다. 그래서 Unicode 디코딩과 `ReadLineAsync()` 제한 시간 대기를 함께 반영했다.

## 행 파일 보강

행 2.19.12에는 아래 여덟 변경을 적용했다.

1. 새 실행 좌표를 `C:\cdda\build\turn-21912-final-test-game2`로 지정했다.
2. 기존 실행 좌표와 기존 보고를 읽기 전용 실패 증거로 지정했다.
3. 행 2.19.9 예외 기록, 성공 보고, `repro7` 실행기를 정본에 추가했다.
4. ProcDump의 Microsoft 서명 검사를 실행 전에 지정했다.
5. ProcDump 선기동과 UTF-16LE 디코딩을 지정했다.
6. `ReadLineAsync()` 제한 시간 대기를 지정했다.
7. 별도 PowerShell 프로세스로 `test-game.ps1`을 직접 실행하도록 지정했다.
8. 종료 코드, 출력, 복원 결과, terminal 체크포인트의 기록 순서를 지정했다.

행 2.19.12의 파견표 상태를 `미착수`로 바꿨다. 행 2.19.7과 행 2.19.8의 선행 관계는 바꾸지 않았다.

## 검산

지급된 검산 명령은 exit 0이다. 출력은 `[dag_check] 무발견 (drive: 서식·어휘·칸 계약·폐쇄·수렴·순환·좌표 실재·게이트 결정·운전)`이다.

지급된 마커 명령은 하위 명령이 없어서 사용법을 출력하고 exit 1로 끝났다. 행 2.19.12는 싱크가 아니므로 lease와 마커 상태를 바꾸지 않았다.

## 반증 의무

이번 실패가 행 2.19.7과 같은 장기 실행 하네스 강제 종료라는 설명은 실행 시간과 로그 종결 문면에 어긋난다. 행 2.19.12가 행 2.19.9의 수정된 실행기를 재사용했다는 설명도 파견문과 실행기 실물에 어긋난다.

직접 원인은 확정하지 않았다. 원 실행이 오류와 종료 코드를 남기지 않았기 때문이다. 그 외 반증은 없다. 검사 범위는 파견표의 행 2.19.12와 선행·후행, 행 2.19.12 파견문·보고·반환·로그, 기존 실행 좌표, 현재 프로세스, 행 2.19.7·2.19.9 예외 기록, 행 2.19.9 성공 보고와 `repro7` 실행기다.
