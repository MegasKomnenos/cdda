# 새 테스트 하네스 연결

## 브리핑

사용자는 테스트 실행을 구현 작업의 실제 위험에 맞추라고 지시했다. 사용자는 정확한 테스트 이름을 호출자가 고르게 했다. 사용자는 논리 조각 단위 재개와 프로세스 실패의 자동 재시도도 지시했다.

현행 활성 DAG는 삭제된 `C:\cdda\test-game.ps1`을 사용한다. `결정/사용자확정-전체실행일원화.md`는 전체 테스트를 행 2.19.6 한 번으로 모았다. 새 하네스는 표적 테스트와 전체 인수 테스트를 다른 책임으로 분리한다.

새 하네스의 실행 정본은 아래 여섯 파일이다.

- `C:\cdda\build-tests.ps1`
- `C:\cdda\run-tests.ps1`
- `C:\cdda\verify-test-data.ps1`
- `C:\cdda\test-harness\TestHarness.psm1`
- `C:\cdda\test-harness\test-harness.ps1`
- `C:\cdda\cataclysm-dda\tests\test_main.cpp`

## 메인 결정 (사용자 축자 아님)

1. 이 결정은 `결정/사용자확정-전체실행일원화.md`의 테스트 실행 위치를 승계한다. 이전 결정의 역사 기록은 보존한다.
2. 일반 구현 행은 수정한 동작을 직접 검사하는 정확한 테스트 이름만 실행한다.
3. 일반 구현 행은 소스를 고친 뒤 `build-tests.ps1`로 빌드 기록을 한 번 만든다. 같은 빌드 기록의 테스트 실행은 빌드를 반복하지 않는다.
4. 작업자는 수정 범위를 확정한 뒤 정확한 테스트 이름과 논리 조각을 자식 행에 기록한다. 와일드카드, 태그, 부분 문자열, 빈 목록, 중복 이름은 허용하지 않는다.
5. 일반 구현 행은 `verify-test-data.ps1`을 실행하지 않는다. 데이터 정의, 로더, finalization, consistency를 바꾼 행만 데이터 검증 책임을 가질 수 있다.
6. 행 2.14는 최종 빌드 기록을 만든다. 행 2.14는 데이터 검증, 전체 일반 테스트, 기능 인수, 성능 인수를 결합한다.
7. 전체 일반 테스트 집합은 최종 빌드 기록에서 `hidden: false`인 이름 전건을 추출해 고정한다. 행 2.14는 고정한 이름을 명시적 JSON 명세로 보존한다.
8. 행 2.15, 검증런, 노드 싱크, 행 2.z, 행 3, 행 z는 기존 `result.json`과 해시를 판정한다. 같은 전체 테스트를 반복하지 않는다.
9. 테스트 실패는 완료된 테스트 결과다. 프로세스 충돌, 예기치 않은 종료, 진행 정지는 프로세스 실패다.
10. 프로세스 실패에서는 `run-tests.ps1`이 미완료 논리 조각을 다시 실행한다. 외부에서 제어기가 중단되면 호출자는 `run-tests.ps1 -Resume <실행 디렉터리>`로 재개한다.
