## 맥락

M-0012의 푸시 뒤 상위 저장소 `main`의 서브모듈 포인터가 `cataclysm-dda`의 로컬 커밋 `3092abfcfcb`를 가리켰다. 서브모듈의 원격은 업스트림 `cleverraven/cataclysm-dda` 하나라서 이 커밋을 받을 곳이 없었다. 그래서 다른 곳의 `git submodule update`가 실패하는 상태였다. 로컬 `master`는 업스트림 기반 커밋 `f84af65`보다 커밋 3개 앞서 있었다. 세 커밋은 Windows 턴 CPU 프로파일러, 테스트 상태 격리와 캐시 수명 보완, 재개 가능한 선택 테스트 실행 계약이다.

해결안으로 GitHub 포크와 새 비공개 저장소를 제시했다. 사용자는 둘 대신 정리 커밋을 직접 만들라고 지시했다. 포크는 공개 저장소의 포크라 항상 공개된다. 새 비공개 저장소는 서브모듈이 `blob:none` 부분 클론이어서 업스트림 전체 이력의 blob을 먼저 받아야 한다.

## 한 일

- 로컬 커밋 3개를 `git format-patch`로 `patches/cataclysm-dda/0001`~`0003`에 뽑았다. 기반 커밋 `f84af65`의 트리를 임시 인덱스에 읽고 세 패치를 `git apply --cached`로 차례로 적용했다. 그 결과 트리가 `master`의 트리 `fa8b4f1`과 같았다. 적용·갱신 절차는 `patches/cataclysm-dda/README.md`에 적었다.
- 상위 저장소의 서브모듈 포인터를 `f84af65`로 되돌렸다. 로컬 서브모듈의 작업 트리와 `master`는 건드리지 않았다. 그래서 로컬 `git status`는 앞으로 ` M cataclysm-dda`(새 커밋)를 계속 보인다.
- `.gitattributes`에 `patches/**/*.patch -text`를 넣었다. `core.autocrlf=true`가 체크아웃 때 패치를 CRLF로 바꾸면 `git am`이 적용하지 못하기 때문이다.
- commit-harness 검증 게이트에 서브모듈 포인터 게이트를 더하고 `.agents` 미러를 재생성했다. `--check`는 드리프트 없음으로 exit 0이었다.

## 터득한 것

- `.gitmodules`의 `ignore = all`은 스테이징을 막지 못한다. git 2.50 임시 저장소에서 시험하니 `git add -A`와 `git commit -a` 모두 새 서브모듈 포인터를 스테이징했다. `git status`와 `git diff --cached`는 그 변경을 보여 주지 않았다. 포인터가 아무 표시 없이 다시 로컬 커밋을 가리키게 되므로 이 설정을 쓰지 않았다. 확인은 `git ls-files -s cataclysm-dda`로 인덱스의 포인터를 직접 읽어서 한다.
- `git format-patch`는 한글 커밋 제목을 파일 이름에서 지운다(`0002-.patch`). 파일 이름은 영문으로 고쳐 달았다.
- 서브모듈 `src/game_io.cpp`·`src/init.cpp`의 미커밋 표시는 내용 차이가 없는 개행 표시였다. `git diff`가 비어 있었다. 되돌리는 `git checkout --`는 권한 분류기가 거부해 그대로 두었다.

## 남은 작업

- 이 방식은 서브모듈 로컬 커밋이 늘 때마다 패치를 다시 뽑아야 한다. 패치가 낡아도 기계가 막지 않고, commit-harness 게이트가 절차로 막는다. 서브모듈 커밋이 잦아지면 포크나 비공개 원격으로 옮기는 것이 낫다.
- `.agents/AGENTS.md`·`.claude/CLAUDE.md`의 미커밋 편집은 이 작업 이전부터 있었고 이번에도 커밋하지 않았다.
